### 1.3 RL 환경 실효 정확도 추정 근거

- **RL 학습**: 0-shot — 프롬프트에 포맷 지시가 포함되지만, 예시 없이 모델이 자력으로 포맷 생산

유사 모델의 실측 데이터 (simpleRL-Zoo 프로젝트):

| 모델 | 벤치마크(4-shot) | RL 시작 시 실효 | RL 후 |
|------|:---------------:|:--------------:|:-----:|
| Qwen2.5-0.5B-Base | — | 36.7% | 49.5% |
| Qwen2.5-1.5B-Base | — | 55.7% | 74.4% |
| Qwen2.5-7B-Base | 85.36% | 88.2% | 91.7% |

Qwen3-4B-Base는 벤치마크에서 Qwen2.5-7B-Base(85.36%)를 상회(87.79%)하지만,
Base 모델의 RL 환경 실효 정확도는 벤치마크보다 훨씬 낮다.
Qwen3-8B-Base가 RL에서 62%로 시작한 점을 고려하면, **4B-Base는 ~45-60%**로 추정된다.

> **이 추정의 불확실성**: 실제로는 다운로드 후 GSM8K에서 단순 생성을 돌려 포맷 매칭률을

### 1.4 Base 모델 선정 이유

| 기준 | Instruct (~85% 시작) | **Base (~50% 시작)** |

이 3단계 전이가 Base 모델에서만 자연스럽게 발생한다.

### 2.4 보상 분포와 |Â| 폭발 수학

G=16, 정답률 p일 때 (이진 보상 {0, 1}):

```
k = 정답 수 ≈ p × G
mean = k/G = p
std  = sqrt(p(1-p)/G × G/(G-1)) = sqrt(k(G-k) / (G(G-1)))
```

| 정답률 p | k/G | mean | std | Â_wrong | Â_correct |
|:--------:|:---:|:----:|:---:|:-------:|:---------:|
| 50% | 8/16 | 0.50 | 0.52 | -0.97 | +0.97 |
| 69% | 11/16 | 0.69 | 0.48 | -1.43 | +0.65 |
| 81% | 13/16 | 0.81 | 0.40 | -2.03 | +0.47 |
| 88% | 14/16 | 0.88 | 0.34 | -2.55 | +0.36 |
| 94% | 15/16 | 0.94 | 0.25 | **-3.75** | +0.25 |

**핵심 관찰:**
- 정답률 80%+ 에서 |Â_wrong| > 2.0 — 감쇠 개입 영역
- 정답률 94%에서 |Â_wrong| = 3.75 — 확실한 폭발 영역
- 정답률 50%에서는 대칭적 → 감쇠 필요 없음

## 3. 핵심 실험 변수: G (rollout.n)

### 3.1 G의 역할

G(group size)는 프롬프트당 생성하는 응답 수이며, GRPO advantage 계산의 그룹 크기를 결정한다.

```
GRPO advantage:  Â_i = (R_i - mean(R_group)) / (std(R_group) + ε)
```

G가 클수록:
- 그룹 내 분산 추정이 안정적 (통계적 장점)
- 하지만 소수 오답의 |Â|가 급격히 커짐 (이 실험의 핵심 변수)
- 스텝당 생성량 증가 (compute 비용)

### 3.2 G 선택: 16

| G | |Â|_max (94% 정답) | 스텝당 총 샘플 수 (batch=32) | 판단 |
|:-:|:-----------------:|:---------------------------:|------|
| 4 | 1.73 | 128 | |Â| 폭발 미미 — 부적합 |
| 8 | 2.65 | 256 | 경계 수준 |
| **16** | **3.75** | **512** | **폭발 충분, compute 적절** |
| 32 | 5.48 | 1024 | 강한 폭발이지만 느림 |

**G=16을 선택한다.** G=4(기존 실험)에서는 |Â| 최대값이 1.73으로 감쇠 효과를 관찰하기 어렵다.
G=16이면 성공률 94%에서 |Â| = 3.75로, 감쇠 함수의 작동을 확인할 수 있다.

### 3.3 train_batch_size 결정

```
총 샘플/스텝 = train_batch_size × G
             = 32 × 16 = 512

steps_per_epoch = 7473 / 32 = 233 (drop_last)
```

기존 설정(batch=64, G=4 → 256 샘플)과 비교하면 2배.
4× H100에서 4B 모델로는 충분히 처리 가능하다.

### 4.1 하드웨어

### 4.2 메모리 추정

```
학습 모드 (FSDP):
  모델 가중치:      8GB / 4 GPU = 2GB/GPU
  옵티마이저 (AdamW): 8GB * 3 / 4 GPU = 6GB/GPU
  Gradient:        8GB / 4 GPU = 2GB/GPU
  Activation:      gradient checkpointing으로 제어
  ────────────────────────────
  합계:            ~10-15GB/GPU (80GB 중)

추론 모드 (vLLM):
  모델 가중치:      8GB
  KV 캐시:         gpu_memory_utilization=0.6 → ~48GB
  ────────────────────────────
  합계:            ~56GB/GPU (80GB 중)

→ 4× H100에서 충분한 여유
```

### 4.3 시간 추정

```
스텝당:
  Rollout (vLLM): 32 prompts × 16 응답 × ~200 토큰 = ~100K 토큰
    4B on H100, TP=1: ~15-25초
  Training (FSDP): 512 샘플, micro_batch=4/GPU
    → ~10-15초
  ────────────────
  스텝당: ~30-45초

1 epoch:  233 steps × ~40초 ≈ 2.5시간
2 epochs: ~5시간
3 epochs: ~7.5시간

실험 2회 (GRPO vs GRPO+dampening): ~10-15시간 총
```

## 5. 예상 학습 역학

### 5.1 세 단계 전이 가설

```
Phase 1: 탐색기 (Step 0~50, 정답률 45-60%)
─────────────────────────────────────────────
  - 모델이 #### 포맷 학습 중
  - |Â| 범위: 0.5 ~ 1.5 (온건)
  - Â 감쇠: 거의 미개입
  - 예상: 두 조건 간 차이 없음

Phase 2: 성장기 (Step 50~150, 정답률 60-80%)
─────────────────────────────────────────────
  - 수학 추론 능력 향상
  - |Â| 범위: 1.0 ~ 2.5 (증가 시작)
  - Â 감쇠: 간헐적 개입 (|Â| > threshold인 샘플)
  - 예상: 미세한 차이 시작 (학습 variance)

Phase 3: 포화기 (Step 150+, 정답률 80%+)
─────────────────────────────────────────────
  - 대부분 정답, 소수 오답에 |Â| 집중
  - |Â| 범위: 2.0 ~ 4.0+ (폭발)
  - Â 감쇠: 적극적 개입
  - 예상: GRPO 단독은 variance 증가, 감쇠는 안정 유지
```

### 5.2 관찰 불확실성

| 가설이 맞을 때 | 가설이 틀릴 때 |
|--------------|-------------|
| Phase 3에서 GRPO의 reward variance 증가, 감쇠는 안정 | 두 조건 모두 안정 (4B가 90%+에 도달 못 함) |
| loss spike 빈도: GRPO > 감쇠 | loss spike 자체가 드물어 차이 미미 |
| 최종 성능: 감쇠 ≥ GRPO | 동등 (이 경우에도 "no harm" 확인) |

> **최소 성공 기준**: "감쇠가 학습을 해치지 않는다" — 최종 성능이 GRPO 이상이면 성공.
>
> **이상적 성공 기준**: Phase 3에서 측정 가능한 안정성 차이 + 최종 성능 동등 이상.
